Zen Word：动态难度到底怎样实现

2.44.0 · XAPK 原生代码核对 · 2026-10-15

核心规则直接展示；触发公式、概率和替代限制可按需展开。

有，已确认存在条件式动态降难度。玩家在一关中尝试较多，隔较长时间回来后，系统可能扩大可用于过关的词语范围，并免费揭示一个字母。这条机制按当前处境和流失标签帮助玩家，没有读取主线 ELO 能力分。

1. 什么时候触发

检查项实际规则
关卡状态重新进入有存档的未完成关卡；排除连词链模式。
进度／资历当前关号≥100，累计游玩天数 PlayDays≥3。不是安装满3天就自动满足。

等待时间half_level_easier_test3 为1或2：至少6小时；其他值：至少24小时。
尝试量本关已填答案、已收额外词与失败试词记录满足下方公式。
流失门槛根据 test2 分组、远端 churn_prob 和衰减天数放行或抽概率。

6小时或24小时，从“上次进入这关”开始算。每次进入都会把时间更新为当前时间，即使这次未获得帮助也会更新。它不是从退出游戏算，也不是在关内停留几秒自动触发。

例如10:00进入、12:00退出、16:00回来，距上次进入已过6小时，满足6小时组的时间要求；是否获得帮助还要看其余条件。

展开：系统如何判断“尝试得多，推进得少”

A＝存档中已完成的答案记录数；E＝已收集的额外词数；T＝失败试词记录数。原代码确实计算 A−E，不能省掉减去额外词这一步。

T 只在判定为“错误词”或“长度错误”时加1。重复提交已经完成的答案或已经收过的额外词，虽然可能有其他错误统计，不会增加这个 T。不到2个字母不计入；至少2个字母但短于本关最短答案时，是否记作长度错误还受判词实验控制。

这套公式用来识别当前关的受阻状态，没有把玩家永久划成“低能力档”。本次也核对了写入端：答案与额外词分开记录；A−E 不是一个叫“净目标完成数”的现成字段。代码没有把负差值强制归零。

这里的天数从该机制的衰减计时首次登记日期算起，按本地自然日差计算；不是安装天数，也不是离开这关的小时数。代码把字段叫“首次触发时间”，实际在第一次进入衰减天数计算时登记。第2组流失值＞0.5的路径直接通过，不会在这里登记日期。

churn_prob 由远端标签数据提供。客户端只读取数值、判断门槛并抽概率；安装包没有包含后台如何算出这个数值的模型，不能据此认定它由 ELO 换算而来。

2. 触发后，关卡到底怎么变容易

第一种帮助：让原来只能收进额外词包的部分词，也有机会填答案。每关有答案词、普通额外词，以及“只能算额外词”的限制列表。触发时，把最后一类移入普通额外词池，并清空限制列表。

玩家随后连出其中一个词时，系统可以用它替换一个现有答案，再把这次输入按答案成功处理。答案格子的数量不变，但可接受的答案范围变宽。被换下来的原答案转到额外词表示中。

展开：哪些词能替代，哪些仍不能
  • 当前策略必须开启“额外词与答案互换”。普通策略还有起始关号配置，缺省值为16；预装引导也有单独放行路径。帮助分支不会强行打开这个总开关。
  • 输入必须已经在本关额外词数据中、尚未被收集、至少2个字母，并符合当前答案长度范围。不能拿任意词典词直接塞进去。
  • 替代词与被替换答案必须长度相同；已经显示的字母必须在对应位置完全一致。因此已完成的答案也不能被换成另一个拼写。
  • 必答名单中的词不能替换；被选中的替换对象若在释义提示保护名单中，这次也不执行替换。
  • 有序模式还检查前后词的“词长优先、同长度按字母序”位置。无序模式省掉这一项；两种模式都保留长度、已揭字母和保护名单检查。

示意例子：一个4格答案原为 TEAR，RATE 原来在“只能算额外词”里。若互换功能开启、该答案没有受保护、已揭字母不冲突，并通过当前模式的顺序检查：帮助后再连 RATE，可以把这4格改为 RATE 并完成它。帮助前连 RATE 则只收额外词。若 RATE 已经收过，就不能靠重复提交再完成答案。

实现：onlyExtra → extra，清空 onlyExtra，写入 AdjustExtraConfigRatio=1。随后正常判词流程完成替换。这个“1”不能直接解释成所有额外词都100%能替换；恢复检查也把它用作保留改动状态的条件。

第二种帮助：免费揭示1个字母。要求 half_level_easier_test3=2，而且前面的时间、尝试量和流失门槛均已通过。本次提供的 Android 执行库在这一组直接进入揭字方法，没有再额外抽一次50%。

  • 只从尚未完成的答案里选。
  • 排除已经提示过的格子，以及金币、盲盒、奖励箱、瓶子、蛹广告、纸飞机、提示广告、烟花广告等被记录为特殊用途的格子。
  • 一个词排除这些位置后，必须还剩至少2个可揭位置，才进入候选池；只差最后一个普通字母的词不选。
  • 把所有合格位置合在一起，随机取1格。是按“格子”抽，不是每个词等概率，所以剩余合格格子较多的词更容易被选中。
  • 没有合格位置就不揭字，额外词池的放宽仍可执行。这条方法不扣金币、不消耗提示道具、不要求看广告，也没有增加普通提示使用次数。

3. 同一关能不能再次获得帮助

可以再次进入判定；本分支没有每关只触发一次的开关。但每次进入都刷新时间，下一次仍要重新等待6或24小时，并再次通过进度、实验与流失检查。

  • 额外词池第一次放宽后已保存到该关配置，再次触发时，已清空的限制列表不会凭空增加新词。
  • 揭字组可以在之后符合条件的回访中再揭1格；已揭位置会排除，不重复抽同一格。
  • 函数没有固定“最多送几次”的计数上限；限制来自时间、概率、未完成词和剩余合格格子数。它不会用这一揭字规则直接补完最后一格。
  • 触发帮助不会清空此前的失败试词和答题进度。换关后按新关重新判断；衰减日期则保存在玩家数据中，不是每关重新从第0天开始。

4. 它和能力分、五个关卡库是什么关系

这条已证实的链路是：当前关受阻＋间隔回访＋实验／流失标签 → 放宽答案范围／免费揭字。调用过程中没有读取主线两份 ELO，也没有把 ELO 分数映射成五档关卡库。

五个关卡库的包内分流，仍主要由地区、语言、平台、付费状态和策略决定。新手活动的“能力＋意愿”分档会改变活动目标关号，是另一套系统。当前没有证据支持“ELO越高就自动换更难词库，越低就自动换更易词库”。

补充：还有一套会改关卡的每日暖场机制

它在冷启动时检查游玩日是否变化，由独立策略开关控制。已有一关未完成时，以后面的新关作为暖场起点。属于按回访节奏调整内容。

  • 暖场重排：维护接下来的15个位置，读取关卡配置的参考耗时，从中选较短的3项调到前面。不是读取玩家 ELO 来选3关。
  • 暖场减词：关号7～1000范围内，按“从本次暖场起点前进了几关”读取预设删词数量。随包 T1／T1_WordTime 的每行有3项，对应暖场前三关的位置。
  • 按关卡预设的候选词顺序，从答案中移除指定词并放入额外词池。实际数量还受候选数量与保底限制：英语至少保留4个答案，其他语言至少保留3个。
  • 例如参考表一行写 [2,1,1]：同一个底层关卡若落在暖场第1个位置，可请求减2词；若落在第2或第3个位置，可请求减1词。不是同一关分三次累计删4词。

两条暖场入口共用当天标记，重排入口先执行；不能把两种帮助视为每个账号每天都叠加。是否开启、加载哪张表仍由策略决定。这里同样没发现主线 ELO 数值参与判断。

实现顺序与核查证据

恢复存档 → 检查关卡／游玩日／实验 → 计算尝试门槛 → 检查距上次进入时间 → 按流失组抽概率 → 可选揭1字 → 放宽额外词池 → 恢复游戏画面 → 更新本次进入时间。

玩家提交单词时，再走“本关额外词存在且未收集 → 功能与长度检查 → 找兼容答案 → 交换词语与格子内容 → 判为答案成功”。帮助入口本身不自动完成额外词。
