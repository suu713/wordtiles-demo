# WordTiles · 单词消消 Demo V1

实现用户粘贴需求中的第一版规则：固定 3×3 棋盘，5 个不重复目标，长度 3、3、3、4、5。只允许上下左右连接、允许转弯、同一词不能重复经过同一格。松手提交，正确目标一次性扣次数；归零格留空，棋盘不移动。

鼠标、触屏和键盘均可试玩。界面包括目标空格、当前连词、随机生成、按 seed 生成、取消、固定样例、重开、提示和 JSON 导入/导出。调试面板默认折叠，分别显示路径数、消耗集合数、逐格次数、32 状态校验结果和生成失败原因。

## 本地运行

无需安装游戏运行依赖，无需构建，无需网络词典。使用 Node.js 20 或更新版本：

```powershell
cd C:\Users\huyi\Documents\ChatGPT\word\wordtiles-demo
npm start
```

在浏览器中打开 `http://localhost:4173`。Windows 也可以双击 `Start-WordTiles.cmd`，启动脚本优先使用已安装的 Node，找不到时尝试本机 Codex 附带的 Node。

请使用 HTTP 服务打开页面；直接双击 HTML 的 file 协议无法正常加载 ES modules、JSON 词库和 Web Worker。服务默认只绑定本机地址，可通过环境变量 `PORT` 修改端口。

## 玩法

- 按住字母拖动，松开鼠标或手指时提交。连到前一个格子时撤回一步；其他已选格、不相邻格和空位均不追加。
- 当前路径经过 `FEE` 时不会提前提交，因此可以继续连接 `FEED`。
- 右上角圆点表示该格剩余次数。非目标、重复目标、非法提交和取消操作不消耗次数。
- 键盘：方向键移动焦点，空格选格，Backspace 撤回，Enter 提交，Esc 取消。
- 提示显示一个未完成目标的单词和带顺序编号的路径；玩家仍需手动连接。
- 五个目标都完成且九格次数都为零时通关。不设置倒计时、步数、生命、额外奖励或难度分级。

## 模块与数据

```text
dist/
  index.html, styles.css, app.js  界面和输入，不拥有扣减规则
  dictionary.json               独立本地白名单
  sample.json                   固定验收样例
  core/rules.js                 DFS、独立校验器、GameSession 原子提交
  core/generator.js             seeded 联合选词/铺路回溯、预算与剪枝
  generator.worker.js           独立生成线程

scripts/                        本地服务、100 seed 批量验收、浏览器验收
reports/                        实际运行结果与桌面/手机/通关截图
```

JSON 关卡格式以 `dist/sample.json` 为准：

```json
{
  "schemaVersion": 1,
  "seed": "your-seed",
  "algorithmVersion": "wordtiles-v1.0.0",
  "board": {
    "rows": 3,
    "cols": 3,
    "letters": ["E", "F", "L", "Y", "E", "A", "P", "E", "D"],
    "counts": [1, 2, 2, 1, 3, 2, 1, 3, 3]
  },
  "targets": [
    {"word": "EYE", "path": [0, 3, 4]},
    {"word": "FEE", "path": [1, 4, 7]},
    {"word": "LAD", "path": [2, 5, 8]},
    {"word": "FEED", "path": [1, 4, 7, 8]},
    {"word": "PEDAL", "path": [6, 7, 8, 5, 2]}
  ]
}
```

格子编号按行排列为 0～8。字母和次数均为固定九项数组。`path` 是参考答案；玩家提交时根据真实字母与邻接关系验证，允许所有合法走法。导出始终导出本关初始数据，包含 seed；再次导入从完整棋盘开始。生成关卡额外保留 `generation` 中的词库版本和搜索预算。

词库加载时统一转大写、去重并剔除非纯字母或长度不为 3～5 的条目。本地词库包含固定样例的全部五个单词，超过 100 个候选词。词频、难度与目标用户适配仍需人工审核。

## 校验与不会卡死的条件

所有关卡进入 GameSession 前都经过独立校验，生成成功和 JSON 导入均无例外：

1. 检查数据格式、3×3 尺寸、目标长度/去重/白名单、1～3 次范围、总和 18 和参考路径。
2. 根据最终字母重新搜索每个目标的所有合法路径，按排序后的格子签名分组。没有路径或有多个消耗集合都拒绝；`EYE` 正反走法同属一个集合，因此接受。
3. 使用唯一消耗集合重新反算逐格需求，并与初始次数逐格核对。
4. 完整检查 32 种完成状态：无负次数、所有未完成词仍有路径、剩余总和等于未完成词长度总和，全部完成后九格恰好归零。

游戏每次成功提交都先完整验证，再同步一次性扣减与标记完成，最后更新表现。次数始终等于未完成目标对该格的需求；某个目标尚未完成时，它所需每格至少剩 1 次。异常会显示“关卡状态异常”，并记录期望次数、实际次数与无法到达的目标。

初始关卡保存为深拷贝并冻结。重开创建新会话；九个格子节点一直保留。表现使用 CSS 动画，动画回调不参与扣次数。切关、重开和新生成均终止旧 Worker，并通过请求编号和关卡版本过滤旧结果。JSON 文件异步读取也校验版本，避免迟到的导入覆盖新关。

## 自动生成

使用 seeded PRNG 和词库前缀树，按 5、4、3、3、3 联合搜索单词和四向路径。每个分支复制字母、次数和目标状态。路径递归禁止重复格、不同字母冲突和超过三次使用；未填字母在唯一集合检查中视为不可用。检查覆盖下界、剩余容量和已放目标的消耗集合歧义，最终执行完整校验。

同长度的三个目标按字典序选择，消除等价的目标排列；铺词路径方向不会提前合并。每次路径递归展开、目标放置、唯一性检查和最终校验的 DFS 都计入预算。

默认每次尝试 10,000 节点，最多 30 次，总计 300,000 节点；调试面板可以修改参数。相同算法版本、标准化词库、预算和 seed 可复现结果。不同 seed 不保证不同棋盘。达到预算明确报告失败，保留当前关卡，不自动替换成样例。取消通过终止 Worker 立即结束生成。

## 验收与复跑

```powershell
npm test
npm run test:batch
npm run test:browser
```

前两项无需安装依赖。浏览器验收需要 Playwright 和已安装的 Chrome 或 Edge；本机自动使用 Codex 附带的 Playwright。其他机器可先运行 `npm install --no-save playwright`。浏览器验收前先保持 `npm start` 运行。

- `tests/rules.test.mjs`：独立 32 状态校验、实际 GameSession 的 120 种完成顺序、EYE 双向、歧义拒绝、前缀词、无效/重复提交、次数配错、初始数据保护、异常状态与词库清洗。
- `tests/generator.test.mjs`：真实生成、相同种子复现、独立再校验、实际清空、路径节点预算、小预算失败、取消和不足词库。
- `reports/batch-100.json`：真实运行 `batch-000`～`batch-099`；逐个记录 seed、结果、节点、剪枝原因、耗时和生成 JSON，成功结果再次完整校验并经实际提交清空。
- `reports/browser.json`：桌面真实鼠标、手机触摸、松手提交、回退、重复词、空位占位、键盘、提示、通关、JSON 读写、Worker 复现、失败保留、取消与切关隔离。

已运行的 100 个 seed 全部成功，所有成功关卡通过完整校验。这是本批样本的结果，不是任意 seed 的成功率承诺；详细结果以保存的报告为准。
